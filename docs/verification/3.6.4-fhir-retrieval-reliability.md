## 1. How it was tested

`FHIRServiceReliabilityVerificationTest` starts a local HTTP server that stands in for the Blue
Button FHIR API and drives the real HAPI FHIR client through `FHIRService`, so every request,
header, query and pagination link is real. No network access or CMS credentials are needed, so it
runs in CI.

To make that possible, `FHIRService` gained a package-private constructor that takes the base URL.
The public no-argument constructor still uses the CMS sandbox, so production behaviour is unchanged.

```bash
cd backend/core
./mvnw -B test -Dtest=FHIRServiceReliabilityVerificationTest
```

Environment: Windows 11, OpenJDK 17.0.20, Maven wrapper, 2026-09-29.

reverted.

## 3. Findings

| # | Finding | Evidence | Suggested fix | Owner |
|---|---|---|---|---|
| F-1 | **Partial failure loses data.** If a later page fails, the exception propagates and the records from earlier pages are discarded; nothing is stored and the caller cannot tell how far retrieval got. | VER-FHIR-08 | Return a result that carries the records retrieved so far plus the failure (or persist per page), as STP-M3-E-02 requires. | Max (3.1.1) / Shayne (3.1.4) |
| F-2 | **No retry or backoff.** HTTP 429 (rate limited) and 503 fail on the first attempt. FR-MCR-23 requires bounded retry on Medicare rate limiting. | VER-FHIR-09 | Retry 429/5xx with exponential backoff and a cap, honour `Retry-After`; never retry 4xx other than 429. | Max / Shayne |
| F-3 | **Records dropped when `Bundle.total` is absent.** `total` is optional (0..1) in FHIR search bundles. The code checks `getTotal() == 0` before reading entries, so a page that omits `total` returns nothing even though it has records. | VER-FHIR-10 | Decide emptiness from `getEntry().isEmpty()`, not `getTotal()`. | Max |
| F-4 | **Minor:** the Coverage path's error message says "Invalid EOB response type", which is misleading when diagnosing a Coverage failure. | Code review | Change the message to "Invalid Coverage response type". | Max |

When F-1 to F-3 are fixed, flip VER-FHIR-08 to VER-FHIR-10 to assert the requirement instead of the
current behaviour.
